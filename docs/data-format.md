# Expected Data Format

Apple Health Atlas accepts a standard Apple Health CSV ZIP export, usually
generated by Health > Profile > Export All Health Data and named something
like `SimpleHealthExportCSV.zip`.

The ZIP contains CSV files whose names begin with an Apple Health type:

```text
HKQuantityTypeIdentifierStepCount_2026-01-01_00-00-00.csv
HKQuantityTypeIdentifierActiveEnergyBurned_2026-01-01_00-00-00.csv
HKQuantityTypeIdentifierHeartRate_2026-01-01_00-00-00.csv
HKCategoryTypeIdentifierSleepAnalysis_2026-01-01_00-00-00.csv
HKWorkoutActivityTypeBadminton_2026-01-01_00-00-00.csv
```

Each file is a CSV table with a common header such as:

```text
sep=,
type,sourceName,sourceVersion,productType,device,startDate,endDate,unit,value
```

Apple Health uses `+0000` style timezone offsets. The app converts records to
the browser's local timezone for daily and hourly aggregation.

Large CSV members are decoded incrementally rather than converted to a single
JavaScript string. This matters for exports with millions of heart-rate rows,
where a single uncompressed CSV can be several hundred megabytes.

## Supported Signals

The parser recognizes common quantity, category, workout, event, and
measurement types. It maps the following groups:

- Activity: steps, active/basal energy, walking/cycling distance, flights,
  exercise time, and stand time.
- Heart and recovery: heart rate, resting heart rate, HRV, respiratory rate,
  oxygen saturation, walking heart rate, VO2 max, and heart-rate recovery.
- Sleep: sleep stages, bed intervals, wake intervals, and nightly wrist
  temperature.
- Body and mobility: mass, height, BMI, blood pressure, walking speed, step
  length, gait asymmetry, double-support time, stability, and stair speed.
- Habits and environment: mindfulness, handwashing, stand hours, headphone
  audio exposure, environmental audio exposure, and high heart-rate events.
- Workouts: any `HKWorkoutActivityType*` file is treated as a workout.

Unknown CSV members are ignored so that future Apple Health additions do not
break the core report.

## Source Priority

When multiple devices record the same signal on the same day, the app chooses
one source per metric/day rather than adding duplicates. The default priority
is wearable devices (such as Apple Watch), then other health applications,
then phones, clocks, and unknown sources. The selected source is available in
the Quality view and in the `coverage`/`selected_source_days` fields when the
aggregator is imported as a library.

## Synthetic Fixture

`tests/fixtures/synthetic-health-export.zip` is generated by
`scripts/build_sample.py`. It contains only fictional sources (`Sample Watch`,
`Sample Phone`) and is used for tests and browser demos. Never replace it with
a real export.
